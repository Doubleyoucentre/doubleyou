# Support and hosted payment link

The homepage introduces the African Impact Hall of Fame in an accessible popup. Its Hall of Fame action uses `/hall-of-fame`; its support action opens the company-owned hosted checkout. Existing ASIP information stays at `/african-student-impact-program`, including the closed application status.

The owner-approved public page is [Doubleyou Impact Support](https://flutterwave.com/pay/eejh5o2ppmas). `src/lib/public-support.ts` supplies this non-sensitive default to the Hall, homepage popup and support section. No secret key, API integration or new payment account is needed for a hosted link.

The **public** build variable `VITE_SUPPORT_PAYMENT_URL` can override the default in the existing Vercel `doubleyou` project. Blank uses the company page; set it to `disabled` and rebuild/redeploy to pause hosted payments and restore the existing bank-support fallback. Invalid non-empty overrides also fail closed through URL validation. All `VITE_` values appear in the browser: never put credentials, tokens, account details or API secrets there.

Supported formats are HTTPS Flutterwave payment/donation pages on `flutterwave.com` under `/pay/` or `/donate/`, and Paystack payment pages on `paystack.com` under `/pay/`. Provider dashboard URLs, temporary transaction sessions, credential-bearing URLs, unknown domains, query strings and fragments are rejected. The bare published company page URL is required. URL validation checks the destination format; the account owner must separately confirm the page belongs to Doubleyou, is in live mode and settles to the intended company account.

When valid, the popup and support section show “Contribute via Flutterwave” or “Contribute via Paystack”. The link opens the provider-hosted page in a new tab. Payment processing stays with that provider. A hosted payment alone does not publish a Hall of Fame profile or prove payment completion; the existing verification/consent/approval workflow remains separate.

The native `/hall-of-fame` page uses a verified Flutterwave hosted page as its **temporary contribution option**. “Contribute Now” opens a native modal with a payment QR code and “Continue to Flutterwave” button. Both use the same current validated public URL; the QR is generated locally with a four-module quiet zone and no external QR service. Supporters scan on another device or open checkout directly in a new tab and choose their amount. The dialog supports keyboard dismissal, a close button and focus return; recognition stays subject to verification, consent and review. The three Hall contribution links share this dialog. Existing homepage popup/support payment buttons continue directly to checkout.

Keep `VITE_HALL_OF_FAME_READY=false` while the full API release is unfinished. A separately accepted exact-origin standalone release takes priority only when that existing readiness gate is explicitly enabled; configuring a hosted link never enables the API. Other provider links are not used by this Flutterwave-specific temporary Hall route.

Create the company page in Flutterwave's intended LIVE environment: Single Charge, company-approved name/description/currency, amount blank so supporters enter their own amount within the provider's limits. Confirm the company identity, environment, currency and receiving/settlement ownership through authorized dashboard access. Do not alter settlement settings, obtain LIVE API keys, or reuse the custom TEST application's return/verification route. Leave any optional custom redirect unset unless separately reviewed; Flutterwave handles the hosted result/receipt.

Before publication, verify the actual public page and company identity, editable amount with at least two different values, currency, allowed payment-method step, mobile/desktop layout and Hall navigation. A real money charge requires an approved amount and payment method; record whether the payment was a genuine TEST transaction, an explicitly authorized live transaction or not executed. Do not describe a page load, fixture test or unsubmitted amount as payment success. All browser test destinations ending `TEST_ONLY` are isolated format/navigation fixtures, blocked from real provider requests; they are not company links or evidence of provider acceptance.

This temporary route records payments with Flutterwave. It does not create a verified contribution, receipt ownership or approved profile in the separate Hall API/database. Public recognition still follows verification, consent and review. Preserve the existing full API work and its TEST-first/LIVE release gates. When the complete reviewed flow is accepted, explicitly transition the destination and archive/disable the temporary company page only through the owner-approved workflow.

Existing bank-transfer details remain available. Test the configured link by checking the actual hosted page and company name without submitting a payment; a completed transaction must be reported separately.
